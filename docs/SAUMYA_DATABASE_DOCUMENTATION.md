# HealthForecastAI - Database Implementation Documentation

## 1. Overview

This document describes the database work implemented for the HealthForecastAI project.

My contribution focuses on the PostgreSQL database layer, including:

- PostgreSQL database setup
- Database schema implementation
- Tables and relationships
- Primary keys and foreign keys
- Data validation constraints
- Database indexes
- Alembic database migrations
- FastAPI and PostgreSQL integration
- Database testing and verification

The main PostgreSQL database used by the application is:

`healthforecast`

---

## 2. Database Technology

The project uses PostgreSQL as the relational database for structured application data.

### Technology Used

| Component | Technology |
|---|---|
| Database | PostgreSQL |
| Database Name | healthforecast |
| ORM | SQLAlchemy |
| Migration Tool | Alembic |
| Backend | FastAPI |
| Database Driver | psycopg |

PostgreSQL was selected for structured data because the application contains multiple related entities such as users, patients, admissions, risk predictions, and treatment outcomes.

---

## 3. PostgreSQL Database Structure

The main database tables are:

1. `users`
2. `patients`
3. `admissions`
4. `risk_predictions`
5. `treatment_outcomes`
6. `audit_logs`

Alembic also creates an `alembic_version` table to track the current database migration version.

The `alembic_version` table is a migration-management table and is not application data.

---

## 4. Users Table

The `users` table stores information about users who access the system.

### Important Columns

| Column | Description |
|---|---|
| `id` | Unique user ID and primary key |
| `email` | User login email |
| `full_name` | Full name of the user |
| `hashed_password` | Hashed password |
| `role` | User role |
| `department` | Department of the user |
| `is_active` | Indicates whether the account is active |
| `created_at` | Account creation timestamp |

### Supported Roles

- Doctor
- Hospital Admin
- Researcher
- System Admin

The email field is unique to prevent duplicate user accounts.

---

## 5. Patients Table

The `patients` table stores patient-related information.

### Important Columns

| Column | Description |
|---|---|
| `id` | Unique patient ID |
| `medical_record_number` | Unique medical record number |
| `age_group` | Patient age group |
| `gender` | Patient gender |
| `race` | Patient race |
| `primary_diagnosis` | Primary diagnosis |
| `assigned_doctor_id` | Doctor assigned to the patient |
| `created_at` | Record creation timestamp |

The `assigned_doctor_id` is a foreign key referencing the `users` table.

The schema uses a de-identified medical record number and does not include patient names, addresses, phone numbers, or dates of birth.

---

## 6. Admissions Table

The `admissions` table stores hospital admission information.

### Important Columns

| Column | Description |
|---|---|
| `id` | Unique admission ID |
| `patient_id` | Patient associated with the admission |
| `admission_date` | Admission date |
| `discharge_date` | Discharge date |
| `time_in_hospital` | Number of days/time in hospital |
| `admission_type` | Type of admission |
| `discharge_disposition` | Discharge information |
| `num_medications` | Number of medications |
| `num_lab_procedures` | Number of laboratory procedures |
| `number_diagnoses` | Number of diagnoses |
| `readmitted` | Readmission information |

`patient_id` is a foreign key referencing the `patients` table.

---

## 7. Risk Predictions Table

The `risk_predictions` table stores the output of the readmission risk prediction model.

### Important Columns

| Column | Description |
|---|---|
| `id` | Unique prediction ID |
| `patient_id` | Patient associated with prediction |
| `admission_id` | Related admission |
| `readmission_probability` | Predicted probability |
| `risk_category` | Low, medium, or high |
| `model_name` | Name of the prediction model |
| `model_version` | Model version |
| `created_at` | Prediction creation time |

The probability is restricted to the range:

`0 to 1`

The risk category is restricted to:

- Low
- Medium
- High

This allows the database to store and track the prediction results generated by the machine learning component.

---

## 8. Treatment Outcomes Table

The `treatment_outcomes` table stores information about treatment and patient outcomes.

### Important Columns

| Column | Description |
|---|---|
| `id` | Unique treatment outcome ID |
| `admission_id` | Related hospital admission |
| `treatment_name` | Name of treatment |
| `medication_change` | Indicates medication change |
| `recovery_score` | Recovery score |
| `length_of_stay_days` | Length of hospital stay |
| `outcome` | Treatment outcome |

`admission_id` is a foreign key referencing the `admissions` table.

---

## 9. Audit Logs Table

The `audit_logs` table records important actions performed in the system.

### Important Columns

| Column | Description |
|---|---|
| `id` | Unique audit log ID |
| `actor_id` | ID of the user performing the action |
| `actor_role` | Role of the user |
| `action` | Action performed |
| `resource` | Resource affected |
| `outcome` | Result of the action |
| `created_at` | Time of the action |

The table provides traceability for privileged actions.
